## 二、坐标系：这一轮用实验定死

D1 的绘制坐标是推出来的，D2 必须先证死，否则点上永远对不准。

做法：在 `Director.ui` 下挂一个 2560×1440 的探针 DrawNode，画三个 100×100 方块，用 `Director:beginGameCapture()` + `captureGameAsync()` 存成 1280×720 的 PNG 再量像素。

| 探针 | 世界/局部坐标 | PNG 实测（左上原点） | 结论 |
| --- | --- | --- | --- |
| 红块 | `Rect(0, 0, 100, 100)` | x 0–49，y 670–719 | 局部原点在**左下**，y 轴**向上** |
| 绿块 | `Rect(400, 0, 100, 100)` | x 200–249 | x 向右为正 |
| 蓝块 | `Rect(0, 400, 100, 100)` | y 470–519 | y 越大越靠上 |

由此定死三条：

1. `DrawNode` 局部坐标原点左下、y 向上，`Rect(x, y, w, h)` 以 `(x, y)` 为左下角向右上扩展。
2. 根节点用 `anchor(0,0)` + `position(-W/2, -H/2)` 后，其局部坐标就等于屏幕坐标（左下原点）。
3. `Mouse.position` 是**窗口逻辑坐标、左上原点、y 向下**，必须换算两次：
   `viewX = mouse.x * View.size.width / App.visualSize.width`，
   `viewY = View.size.height - mouse.y * View.size.height / App.visualSize.height`。

量出来的旁证：检查站地面线在世界 y=0，画布 y=300（房间高 210、视野高 180，垂直居中 → `cam.y=105`，`(0−105)×4+720=300`），PNG 行 570，与实测 568–570 一致。

## 三、输入层

`Input` 每帧 `update()` 读一次物理键，给出 `held / pressed / released` 三态。

- 用**轮询**而不是 `onKeyDown` 回调：窗口失焦时用户在外松键，回调收不到抬起事件，按下态会卡死；轮询读物理键当前状态，切回来自然归零。
- 鼠标左键用 `Mouse.leftButtonPressed` 走同一条边沿逻辑。
- `1`/`2` 选房间带 `lastPick` 去重，避免按住时每帧重进房间。

| 动作 | 键 | 语义 |
| --- | --- | --- |
| 移动 | A / D、← / → | -1 / 0 / 1 |
| 跳（小满） | Space | 边沿触发，初速 320 |
| 翻滚（周戍） | Space | 边沿触发，0.35 秒 |
| 蹲 | S / ↓ / Ctrl | 按住 |
| 慢走 / 贴掩体 | Shift | 按住 |
| 交互 | E | 边沿触发 |
| 瞄落点 / 瞄准 | F | 按住（D5 投瓶用） |

## 四、试玩层

### 数值（与逐日文档第五节一致）

| 项 | 值 |
| --- | --- |
| 小满 | 宽 28、高 64、蹲高 36、走 160、慢走 80、爬行 80、跳初速 320 |
| 周戍 | 宽 30、高 88、速度 264、翻滚 0.35 秒 / 280 速度 |
| 重力 | 1000，下落速度上限 900 |
| 相机 | 4 px/单位，跟随系数 9，视点高于脚底 46 |

### 物理

- 水平 `slideX`：先钳进房间边界，再对每个实体 AABB 做贴边回推（只用当前位置判断从哪一侧顶住，避免抖动）。
- 垂直 `fallY`：重力积分 → 下落时取 `groundAt` 最高落脚面 → 上升时撞实体底面。
- 落脚面 `groundAt`：地板与实体顶面里、不高于脚下容差的最大值。
- 拱洞：身高超出净高 `arch.y + arch.h` 时不许进入；已在洞内的人（蹲着进来再站起来）允许朝任一侧走出，否则会被永久卡死。

### 点射与遮挡

枪口 `(x + facing×8, y + h×0.72)`，目标取准星反算的世界点，方向归一化后做 slab 射线求交：

- 分别求最近敌人距离 `tEnemy` 与最近实体距离 `tWall`；
- `hit = tEnemy >= 0 && (tWall < 0 || tEnemy <= tWall)`；
- 弹道画 0.12 秒；命中把敌人 `alive` 置 false。

站在 225（柜台左侧）朝 430 的敌人射击会被柜台吃掉，站在 380 就能打中——这条是「柜台当掩体」的可玩性来源，先验住了。

### 交互

- E 两次间隔 1.2 秒内 → 「敲两下」，否则「敲一下」。
- `marks` 里 `kind === 0` 且距离 < 26 → 提交本地检查点（城外 380@0）。
- 城外站在板车手柄 `startX + handleOffset = 344` 附近 70 以内 → 手柄亮起「按住 E + A/D 拉车」（真拉车 D3 接）。

## 五、像素化渲染

规划把全局改成 320×180 逻辑画布、1 美术像素 = 2 世界单位。这一节是**镜头与准星**那半（D2 验收项），美术资产铺开在 D5。

### 5.1 三层换算

```
世界单位 → 逻辑像素（除以 2）→ 屏幕像素（乘整数 zoom，再加居中偏移 ox/oy）
```

- `LOGIC_W = 320`、`LOGIC_H = 180`、`UNITS_PER_PX = 2`，一屏正好 640×360 世界单位，与规划的一屏宽度一致。
- `computeViewport(w, h)`：`zoom = floor(min(w/320, h/180))`，下限 1；剩余空间对半分出 `ox`/`oy`，外层铺 `BG_VOID` 当黑边。
- 1080p → 6 倍、720p → 4 倍、1440p → 8 倍，都是整数倍，不出现半像素。

### 5.2 量化在哪一步

**物理和瞄准保留小数，只在画的时候对齐逻辑像素。** 具体是 `sx`/`sy` 先把世界坐标换成逻辑像素再 `Math.round`，然后乘 zoom —— 这样同一根柜沿在任何相机位置、任何缩放下都落在同一列像素上，不会因相机亚像素漂移而闪边。

`drawBox` 先算四个角再判 `px1 <= px0 || py1 <= py0` 跳过退化的块，避免零宽矩形。准星是四臂十字，`dot`/`arm`/`gap` 都按逻辑像素给，先对齐再画。

地面基准 `GROUND_PX = 40`：初值取 `180 × 0.22 = 39.6`，会在地面线上拉出半像素误差，改整数 40 后消失。相机竖向也因此固定：`cam.y = (LOGIC_H/2 − GROUND_PX) × 2 = 100`。

### 5.3 鼠标反算

`screenToWorld` 改成用实际画面原点、显示倍数和本帧相机：

```
x = cam.x + ((sx − ox) / zoom − LOGIC_W/2) × 2
y = cam.y + ((sy − oy) / zoom − LOGIC_H/2) × 2
```

这对应规划里「鼠标反算使用实际画面原点、显示倍数和本帧呈现的相机位置」那条。

### 5.4 验收

| 分辨率 | zoom | 黑边 | 柜角 (340,60) 反算误差 | 柜沿 (240,0) 反算误差 |
| --- | --- | --- | --- | --- |
| 1280×720 | 4 | 无 | 0.000 | 0.000 |
| 1920×1080 | 6 | 无 | 0.000 | 0.000 |
| 2560×1440 | 8 | 无 | 0.000 | 0.000 |
| 1440×900 | 4 | 160×180 | — | — |
| 1280×800 | 4 | 0×80 | — | — |

点选在 `cam.x` = 264 / 400 / 560 三个位置各测一次（对应相机跟随前、跟随中、跟随后），误差都是 0.000 —— 规划要求的「相机跟随前后各点一次，点击仍落在柜角」成立。

像素级抽检 `docs/d2-像素画布-检查站.png`：柜台占 200 px（100 单位 ×2），小满躯干 56 px、周戍 60 px；竖扫 col=320 依次是 `BG_MID` 446 px（恰为 720 × 0.62）、`BG_FAR` 110、地面 8 px（2 逻辑像素 ×4）、地层 16 px（4 逻辑像素 ×4），无渐变无模糊。唯一出现双色的地方是危险区边线（alpha 200）压在不同底色上，不是抗锯齿。

## 六、Windows 小包

官方发布页有现成的 `dora-ssr-v1.10.2-windows-x64.zip`（104.5 MB），与本机开发版本号一致。因此这一轮走 B 路线：**官方 Windows 引擎 + 精简资源目录**，不碰 xmake 原生打包（那条路要 Windows 构建机 + VS C++ 工具链，留作备选）。

### 6.1 包里装什么

从官方发行包解压出的 231 MB 里，只留运行必需：

| 保留 | 说明 |
| --- | --- |
| `Dora.exe`、`dora_godot.dll`、`wa.dll` | 引擎与运行时 |
| `DoraDistribution.json`、`gamecontrollerdb.txt` | 发行标识与手柄映射 |
| `Font/` | 含 `sarasa-mono-sc-regular.ttf`，中文标注就靠它 |
| `Audio/`、`Image/`、`Shader/` | 引擎内置音源、图标、着色器 |
| `Script/Lib/` | TSTL 运行时（`lualib_bundle` 等 741 个文件） |
| `LICENSES`、`GodotRuntimeNotices` | 许可要求 |

删掉：`Doc/`(15M)、`www/`(35M)、`dora-wa/`、`Script/Dev/`、`Script/Tools/`、`Script/Lib/Dora/`、`Script/init.yue`。组装后 172 MB，压 ZIP 66 MB。

### 6.2 入口为什么要分成两层

发行包自带的 `Script/init.yue` 会 `require("Script.Dev.Bootstrap")` 再 `require("Script.Dev.Entry")` —— 双击进的是 Web IDE。要变成游戏，必须删掉它并接管 `Script/init.lua`。

但直接把自己的入口放上去还不行：**TSTL 生成的 Lua 在文件顶部就 `require("Script.watch.app")`**，而这时搜索路径还没设；独立 exe 又不像 Web IDE 那样自带「项目目录/Script」和「项目目录」两条路径，`require` 会直接找不到文件。

所以入口分两层：

- `Script/init.lua`（手写，`tools/windows-boot.lua`）先把 `Content.searchPaths` 定成 `Script` → `Script/Lib` → 语言包 → 资源根，四条，然后 `require("Script.main")`；
- `Script/main.lua` 是 TSTL 生成的入口，此时路径已经就位，照常加载游戏模块。

同时 `init.ts` 里也留了 `ensureSearchPath`，在 Web IDE 下路径本就存在、不会重复添加，只是兜底。

### 6.3 怎么验证的

macOS 上跑不了 `Dora.exe`，于是把包里的 `Script/` 原样搬到 `/tmp/wintest/` 当资源根，用本机引擎以同样的四条搜索路径加载 —— 这验的是「包内文件与模块关系」，验不了 exe 本身：

- `Content.searchPaths` 只剩四条、引擎库只从包里的 `Script/Lib` 取；
- `ui.children = 1`（根节点建起来了）、`require("Script.watch.play")` 返回模块表；
- 截帧 `/tmp/wintest-play.png` 与本地像素风截图 `d2-像素画布-检查站.png` **md5 完全相同**（`7d39a0c6…`），说明包内渲染与本地逐字节一致。

重新组装用 `tools/make-windows-pack.sh`：读 `.download/win/`、套用排除表、装入口与脚本、压 ZIP，一条命令复现。

### 6.4 还没验的

双击 `Dora.exe` 冷启动、Window 下的中文字形与鼠标手感、Windows 的 D3D12 首帧 —— 这些必须在 Windows 机器上做，对应验收 W01。包已经备好，`README.md` 与 `启动.cmd` 都在根目录。

## 八、本轮已知取舍

- 试玩层一帧推进一个 `STEP`，帧率低于 60 时会整体变慢；D3 接固定步累加器。
- 未操控的一方只落体、不跟随；护送逻辑按排单在 D3。
- 拉车只有焦点提示，没有位移；D3 接两侧 dock。
- 敌人不还手、不做巡逻；D4 接危险段与 SoldierDown。
- 美术资产还是几何色块，像素拼块与角色帧动画在 D5；这一轮只把镜头、准星、量化定死。
- 关卡宽度仍是 D1 验收过的 1000 / 600 单位剖面，六区加宽按排期在 D4 接 `originX`。
