## 2. 坐标与前后景

- glTF 为 Y-up，**1 glTF 单位 = 1 米 = 100 游戏单位**；游戏内 `x` 左右、`height` 离地、`depth` 前后。
- 导出映射：`gltf_x = gameX/100`、`gltf_y = height/100`、`gltf_z = -depth/100`。
- **游戏相机位于 `+glTF Z` 一侧**（`updateCamera` 的 `cameraZ = tz + distance`）。因此：
  - **后景（墙、树、桌、梁、门、窗、阻挡线、支柱、低拱、塔身）放在游戏正 `depth`** → `gltf_z < 0`，远离相机；
  - 近相机侧（`gltf_z > 0`，即游戏负 `depth`）只保留地面、台阶、台面等低矮或通行结构，保证角色不被挡。
- 可走带 `game depth ∈ [-0.44, 0.44]`（对应 rooms.ts `LANE_ROAD`）；高于 0.5 m 的后景构件统一落在 `game depth = +0.58`。
- 房间宽度：outside 12.4 m（1240 单位）、village 7.2 m（720）、forest 16.0 m（1600）、tower 7.2 m（720）。

## 3. 源坐标 → 游戏坐标

源 actor 的 UE 坐标（厘米）为 `(x, y, z)`；四房的长轴都取 UE `Y`（+Y 对应游戏 +x 前进方向），横轴 UE `X`，高度 `Z`：

```
gx  = (t - t0) / (t1 - t0) * game_w * 100        # 选段窗口 → 房宽（分段、非均匀）
dep = (s - s_ref) * k                             # 横向压缩
hgt = (z - h_ref) * 100                           # 高度 1:1（米）
```

| 房间 | t0–t1（UE Y） | s_ref（UE X） | k（游戏单位/米） | game_w | h_ref（实测） | h_top |
|---|---|---|---|---|---|---|
| outside | 76–88 | -3.0 | 14.6 | 12.4 m | 4.10 | 7.30 |
| village | -249–-243 | 7.65 | 10.0 | 7.2 m | -9.41 | -6.21 |
| forest | -175–-163 | 0.0 | 7.3 | 16.0 m | 5.74 | 8.94 |
| tower | -300–-288 | -24.0 | 7.3 | 7.2 m | -21.37 | -18.17 |

- `h_ref` 取窗口内演员 `z` 的 10% 分位，`h_top = h_ref + 3.2 m`：只取**近地一层**，避免 20 m 立面塞进 2.2–2.4 m 高的房间。
- 门/窗不受层裁剪：`height` 贴 0（门）或 90（窗台 0.9 m），水平 `gx` 保留源门距/窗距。
- `rot` 数组顺序为 UE 序列化的 `[Pitch, Yaw, Roll]`，**Yaw 在索引 1**；普通 Actor 的朝向按 Yaw 分档（0/90/180/270），阻挡面用同一 Yaw 旋转四边形后再与选段裁剪。
- 阻挡面：`BP_BlockingPlane_C` 的 `FarCornerWidget`（相对 loc 的厘米）→ 旋转 → 裁剪；只保留**后景侧**（`game depth > 0`），近相机侧的阻挡面会挡角色，弃用并计入删减。

## 7. 前端贴图接入

1. 导入 GLB 后保留槽名（`M_xm3d_*`），按对象替换为项目 PBR 材质或直接赋贴图。
2. UV 未展开（只烘焙变换）；贴图接入按世界尺度做三平面/盒式投影，`manifest.json` 提供每个逻辑条目的中心与 `kind`，可按类别分材质。
3. 动态物件（红布车、塔门、拾荒者、瓶、器物）不在 GLB；锚点与它们在 rooms.ts 的碰撞值一致。

## 8. 自检

- 法线：`bm.calc_volume(signed=True)` / 绝对体积比 **1.0000**（四房全部外向）。
- 三角面（实际 `mesh.loop_triangles`）：672 / 676 / 1356 / 1060。
- GLB 包围盒（X × Y 高 × Z 深，米）：12.400×3.343×4.800 / 7.272×3.000×4.000 / 16.300×5.488×4.400 / 10.820×3.000×3.900。
- 近相机侧（`gltf_z > 0`）高于 0.55 m 的构件数为 0（除地面/台阶/台面与通道边缘的侧墙）；三帧实拍复核放 `.cache/xiaoman3d-preview/frame_outside_lower.png`、`frame_village.png`、`frame_forest.png`（相机在 `+Z`，与游戏镜头同向）。
- `manifest.json`：`items` 数与 `boxes` 一致（56/54/78/75），锚点条目 23/25/24/23。
- Dora 实机取景覆盖旧渠（x=745）与溪湾（x=1220），两处水带前后均有连续土岸。对照图在 `.cache/xiaoman3d/banks-after.jpg`。

## 9. 删减与未处理

- 删减：现代设备（AirConditioner、PipeKit、Downpipes、CablePole、BathTub、GreebleKits、WallSwitch 等）、敌人/Nav/AI/CLO、灯光/体积/Decal、选段窗口外演员；`h_top` 以上的高层墙/树只保留门窗水平位置。
- 近似：源 `rot` 只按 Yaw 分档（斜放构件用 AABB）；mesh 尺寸优先解析文件名 cm，缺失时用 `scale`/类别默认。
- 未处理：贴图/UV/灯光；碰撞体导出（碰撞仍由 rooms.ts 的 2D 盒驱动）；动态物件；音效。

## 10. 本轮五处修复

1. **城外低拱车底挡栓**：不再写进 GLB。`fe/scenes/xiaoman3d.ts` 运行时按 `slideX` 同一条件绘制——`outside && !cartDocked && arch.x1>arch.x0` 时，横杆取 `arch.x0..arch.x1 ∩ cartAxle±24`、高 0.40–0.45 m，两根立杆 0–0.44 m；车轮落窝（`cartDocked`）后与碰撞一起消失，只封拱口、不封旁边平地。
2. **村口矮渠入口 560–640**：GLB 加石砌矮拱（左右壁、净高 44 的楣、渠底 −0.08、洞内暗、金属口沿只留底/顶窄带）；`play.ts` 的切房条件改为 `passed && x∈[560,640] && crouch && wantRoom===""`。站姿可走到 672 院墙前但不切房；原地蹲下才钻入并切森林（`storyBeat culvert_enter`）。`verify-child-walk` 4.4/4.5/4.6、`verify-b2-walk`「村口蹲过拱洞到林缘」全 PASS。
3. **森林旧渠 700–790 / 溪湾 1180–1260**：主地板在渠与湾处裁成三段（0–700 / 790–1150 / 1260–1600），露出槽底与水面；水面顶 −0.02（与脚下支撑齐平），灯影薄片 −0.02…0.01 浮在水上；石灯座/灯罩在湾内。运行时叠青色水光与金色灯影（`glow`，随呼吸轻摆），灯 sprite 在 1224。
4. **城外两组石阶**：按 `play.buildWorld` 的 `n=steps+1` 与 `y=y0+(y1−y0)·k/(n−1)` 重排——56–128 为 6 级 0/19.2/38.4/57.6/76.8/96；700–820 为 4 级 0/21.33/42.67/64；首级与地板齐，x 与顶高逐级对齐。
