# 守望 · D5 从序章到北塔

- 仓库：`dora-game`，分支 `feature/watch-d1-graybox`
- 基线：D4 提交 `0bea9d8`
- 验收方式：引擎内逐拍逻辑回放（`tools/replay-d5.lua`）从序章 `Play` 开始，按输入状态推进；脚本读取每个 `wantRoom` 后手动新建下一个 `Play`
- 画面通道：本轮仍不可用，实际键鼠连玩与 Windows 真机单列待测
- D6 追加：守点攻击/失败闭环与回放输入层改造已验（见第九～十一章）

## 独立复核 · 回放覆盖边界

运行 D5 回放后，脚本能从序章开始按 `wantRoom` 顺序覆盖八个 `Play` 段落，复现守点计时、停用方向键后的第 24 秒交权、抓获复位和塔门片尾。应将此结果称为**分段逻辑回放覆盖完整路线**，不要称为已完成默认入口上的完整实机试玩：脚本的 `hop()` 读取 `wantRoom` 后，直接创建下一个 `Play`，没有调用 `app.ts` 的 `tickPlay()` / `ensurePlay()`。

另有三项需要在 D6 验收：

1. `replay-d5.lua` 的街道清敌直接调用 `p:shoot(p.player)`，没有从 `Input.fire` 按下边沿经准星射击。因此枪战操作还需用真实鼠标复演。
2. 回放的村口段在抓获后拾瓶，随后直接蹲过桌下；它没有瞄准、松 F 投瓶或等拾荒者转向。既有 D3/D4 单房回放覆盖了投瓶成功路径，但 D5 整链脚本未覆盖该路径跨帧演出。
3. 当前 `stepEnemies()` 只衰减命中闪烁计时；敌兵有出生与受击退场，没有对周戍开火、玩家受击／体力耗尽和失败回到绞盘检查点的逻辑。D5 表里的守点暂停、敌兵出场、守满送别可以验，守点受击失败分支尚不能验，需先实现再验。

因此目前结论是：回放实现的房间级逻辑覆盖通过；默认入口实际连续游玩、鼠标枪战、村口投瓶整合、守点失败分支及 Windows W01 仍待验。

## 四、城门 45 秒守点

状态机：`gate-idle → gate-hold → gate-send → gate-count → gate-walk`。

- **就位**：小满自己走向等待点 960（卡住会自动起跳，街垒 44）；
  周戍站到绞盘 70 ±60。两者到位即 `gateTick = 0`、进 `gate-hold`。
- **守点 2700 拍（45 秒）**：敌兵按 0 / 9 / 15 / 25 秒四批出场（`gateSpawned` 计数，四个独立出场 ID），
  900 拍闪「灯灭了」、2100 拍闪「门底压下来了」。
- 计时只在非暂停步推进：`stepGate` 在角色与敌兵结算之后读计时，用越过 900 / 2100 / 2700 的那一步更新阶段。

**44 秒暂停再恢复的读数**：

| 读数 | gateTick |
|------|----------|
| 44 秒整（2640 拍） | 2640 |
| 按 Esc 暂停 | 2640（paused=true） |
| 暂停 5 秒后 | 2640 |
| 恢复第一拍 | 2641，剩余 59 拍 |

即暂停期间计时冻结，恢复后从 2640 继续，差 60 拍才满。

## 五、送别、数到一百与交权

- 满 2700 拍且周戍存活 → `gate-send`：撤预警、冻结并清空敌兵。
- 周戍走到门边（860 ±60）**新按一次 E** → `swapToChild(g.doorX + 30)`：
  玩家切成小满（x=890），周戍留在门内，进入 `gate-count`。
- 进 `gate-count` 的当步记 `countArmed = (input.moveX === 0)`。
- `gate-count` 期间演出持有控制：`storyLocked()` 把玩家 vx 清零，只能播动画。
  360 拍关门、1020 拍叠化、1440 拍起数到一百、镜头降到肩高。
- 1440 拍后：若 `moveX === 0` 则 `countArmed = true`；`countArmed && moveX > 0` 的当步进 `gate-walk`。

**交权时的首次输入（两条路径都验过）**：

| 场景 | 读数 |
|------|------|
| 24 秒前没按方向键 | 进 `gate-count` 时 `armed=true`；按住 D 到 1500 拍仍 x=890（演出锁移动）；松开一拍 armed 仍 true；新按 D 当步 `gate-walk`、x=903.3 |
| 24 秒前已按住 D | 进 `gate-count` 时 `armed=false`；按住 D 到 1500 拍 `countTick=1500`、x 仍 890；**松开一拍**才 `armed=true`；再按 D 当步 `gate-walk` |

- 走到 1020 出门，`want=outside`。

## 九、D6 收口：城门攻击与失败闭环

守点不再只是计时与出场。四批敌兵会举枪、开火，周戍有三格体力，被打空回到绞盘重来。

| 项 | 实现 | 数值 |
| --- | --- | --- |
| 预警 | `Enemy.warnT` 归零即开火；`warnT > 0` 时从枪口到周戍画红色虚线准线 | `WARN_TICKS = 36`（0.6 秒） |
| 节奏 | 每名敌兵独立冷却，城门出场时按批次错开 | `FIRE_COOLDOWN = 150`；出场 `fireCd = 90 + idx * 45` |
| 射程 | 覆盖整屏，四批都能打到绞盘 | `ENEMY_RANGE = 760` |
| 应对 | 贴住街垒/柜台（距边缘 < 24）、按 Shift 贴掩体、或打掉敌兵 | `blockedByCover` 要求贴身，站绞盘不贴掩体照中 |
| 受击 | 三格体力，中弹闪「中弹 n/3」 | `hp = maxHp = 3` |
| 失败 | 闪「被击倒 · 回绞盘重来」，计时、敌兵、体力全部重置 | `gateTick = 0`、`gateSpawned = 0`、`enemies = []`、`phase = gate-hold` |
| 复位 | 周戍回绞盘 130，小满回 900 | `gateFailCount += 1` |

## 十四、四项逻辑验收修正（2026-11-22 21:35）

只做逻辑收口，不加关卡、不做美术。四项改动与读数如下。

### 14.1 数数交权：只认上升沿

- `countPrevMove` 记录上一拍方向，第 1440 拍之后才允许 `countArmed` 置真；置真要求 `prevMove <= 0 && moveX > 0`。
- 交互前不再把 D 清零来绕过：送别进数数时只记录 `countPrevMove = input.moveX`，按住的 D 会被如实当成「已经按着」。
- 三种用例（断言 A/B/C）：

| 用例 | 操作 | 读数 |
|---|---|---|
| A 送别时就按住 D | 按到 1500 拍 | `gate-count`、`x=890.0`、`armed=false`；松开一拍仍不走，再按才 `gate-walk` |
| B 第 1439 拍按下并保持 | 保持到 1451 拍 | `tick=1451` 仍 `gate-count`、`x=890.0`；松开再按才 `gate-walk` |
| C 空手到 1440 后新按 | 1440 拍起按 D | 当拍 `gate-walk` |

### 14.2 掩体：Shift 必须贴住

- 旧行为：`p.crouch || cover.held` 无条件挡枪，空地按 Shift 也无敌。
- 新行为：`covered = cover.held && nearCover(a)`；`nearCover` 要求身位与实体水平距离 < 24（半宽贴住），且实体高度 ≥ 44。
- `blockedByCover` 只判「掩体在两者之间」，`enemyFire` 用 `hugging && cover.held` 才算挡下。

### 15.3 实机键鼠连玩：本机未通过

目标是从默认入口用真实键鼠连玩到北塔。**没有做到**，原因不是脚本没写，是注入的键盘事件进不了 Dora 窗口。

为读「真实运行中的那个实例」，在 `app.ts` 挂了两个验收钩子（引擎禁止新建全局，改挂 `package.loaded`）：

```ts
reg["watch.play"] = play;      // ensurePlay() 里，指向当前 Play
reg["watch.input"] = input;    // start() 里，指向当前 Input
```

钩子生效后读到：`room=prologue`、`phase=prologue-wait`、`p=80.0/0.0`、`pt=300.0`、`ticks` 持续增长——游戏确实在跑，实例可读。

按键侧试了四条路，全部无效：

| 尝试 | 结果 |
|---|---|
| `computer_key(foreground=true, "d")` | `x` 仍 80.00 |
| `osascript System Events key down "d"` 按住 1.2 秒 | `x` 仍 80.00 |
| `osascript` 点窗内拿焦点后再按住 D 1.0 秒 | `x` 仍 80.00 |
| `Escape`（应触发暂停） | `paused` 仍 false |
| `computer_key(app="Dora", "f1")`（postToPid） | `play` 未被重建，`ticks` 连续递增 → 开发钩子没触发 |

同时 `package.loaded["watch.input"].moveX` 恒为 0、`inside=false`；窗口侧观测正常：`computer_status` 报 accessibility / screenRecording 均 true，`Dora` 是 frontmost，1 个窗口 1280×752，`View.size=2560×1440`、`App.visualSize=1280×720`。

结论：本机 Dora 收不到合成键盘事件（三条注入路径 + postToPid 都不进），因此**默认入口实机连玩无法由自动化完成**，仍待测。这条不能用 Lua 回放代替——回放是直接构造 `Input` 结构体，绕过了「键 → 窗口 → Input 采样」这一段，正是本轮要验的链路。
