# 《向西守望》逐日开发与代码实现逻辑

工作区沿用简称《守望》，仓库原案题名《月下山谷》。周戍把小满送出城门，小满独自走到北塔。程序由一人承担。交付日为 **2026 年 12 月 1 日**，交付件为解压后能直接启动、从序章玩到片尾的 Windows x64 键鼠游戏。

开工从**一张柜台、两个人和一辆车**开始。11 月 24 日的短片段要回答三个问题：周戍回头敲木板时，小满会不会重新走起来？换人后，玩家能不能认出周戍推过的车，亲手把挡住的洞拉开？站在村口，玩家能不能凭拾荒者的转头决定何时出发？11 月 25 日将这段接入完整故事，之后的六天用于把完整游戏做成可交付版本。

本文的坐标、速度、警觉时间、关卡摆位是首轮灰盒提案。工时和 27 分 30 秒首通时长是预算。目前有 Dora 多文件编译、中文显示、窗口重排和 macOS Edge 离线探针的记录。正式入口仍调用 `Probe.mount(root)`。以下任务从这个真实起点计时。

**故事物件的连续性。** 玩家在序章已经看过小满把针套系在手腕上。城门切线时，针套仍在她手上；改变的是玩家操作谁。北塔才第二次改物主。板车则相反，玩家先改变的是它停在哪里，换了主角以后才看清这个位置的含义。

## 二、一次按键怎样到达屏幕

正式地图按《守望-十日成品规划》的六区宽度拼接。沿用 `rooms.ts` 的段内坐标，在 `makeRoom` 生成角色、地面、车轨、安全点和触发区时统一加该段的 `originX`。例如检查站候检区宽 640，原灰盒装卸台在新地图的 `640 + 768 = 1408`，城外读同一个 `dock` 时仍投影到局部 `304`。检查点记录房间、路段和局部锚点，相机按整区边界跟随。

像素风世界层按 320×180、每像素 2 世界单位出图，1080p 对应 6 倍整数放大。纹理采样用最近邻，常规窗口取能容纳画布的最大整数倍后居中。物理和瞄准保留小数，画图时再把角色相对镜头的位置和各层视差位移对齐到逻辑像素。鼠标反算使用实际画面原点、显示倍数和本帧呈现的相机位置。D2 在 1280×720 和 1920×1080 各缓慢走过同一根柜沿，在相机跟随前后各点一次，检查边缘清晰且点击仍落在柜角。

`mount → 设备边沿 → takeIntent → step → applyOutcome → drawState/playEvents`。模拟采用每秒 60 步。按键边沿是一次按下或松开，持续态是这一步键仍按着。渲染率可以与模拟步数不同。

1. 键盘／鼠标回调只收集输入。左右同时按下时 `moveX=0`。E 按下时选定面前的交互对象；握把类进入持续握持，其他目标执行一次。直到松键前始终属于这个目标，走过下一件道具时不会顺带捡起它。HUD 使用相同的选取函数。
2. 每个渲染帧先处理 Esc。暂停时维持画面，游戏计时、物理和声音时间线停住；菜单仍可用。继续时从当前帧重新计时。更换角色或从暂停返回，记录此刻仍按住的键，逐键松开后才承认它的新动作。
3. `schedule` 累加实际经过时间。每够 `1/60` 秒取一个 `Intent`。一帧赶两个模拟步时，第一个步消费待处理的有序按下／松开，第二个步只读持续态。一个步都没到时，把边沿留到下帧。F 在同一步内按下又松开，仍依次开始瞄准、按松键位置投出。
4. 在游玩态先读交互焦点，再决定角色动作；处理移动、推拉与碰撞，再处理命中、巡逻者已到时的危险、瓶子落地等事件。护送者和巡逻者各读自己需要的事件。最后判定本步结果，同步故事、检查点或房间切换。倒地／抓获优先于同一步的守点到时和出口。
5. 视图画最后一个模拟步的位置，但播放本帧**所有**模拟步提交的声音和动作提示。每条事件带所属房间；切场时将送别声之类的过场声音交给应用层，旧房间的局部提示随房间退场。相机和准星共用同一套坐标变换。

以下为调用顺序伪代码。`advanceMode` 根据游玩、数数或尾声推进当前段落。每步直接更新当前房间，只在写检查点时复制数据。

```ts
function frame(elapsed) {
  if (handleMenuInput() || app.paused) return drawCurrentScreen()
  accumulator += elapsed
  const effects = []
  while (accumulator >= fixedStep) {
    const intent = input.takeIntent(app.inputOwner)
    const result = advanceMode(app, intent)
    applyOutcome(app, result.outcome)
    appendEffects(effects, result.events)
    accumulator -= fixedStep
  }
  present.drawState(app)
  present.playEvents(effects)
}
```

**坐标。** 世界使用右向 `+x`、上向 `+y`，角色原点在脚底。使用无旋转 2D 相机。将 `Mouse.position` 按 `View.size / App.visualSize` 比例从窗口映射至视图，以视图中心为原点，翻转一次 Y，除以缩放后加相机世界位置。若碰撞体用父节点局部坐标，再做一次 `convertToNodeSpace`。以最近一次呈现的相机姿态解释点击位置，射击和投瓶准星用同一函数。世界节点挂世界层；菜单、血格、恐惧、字幕挂 UI 层。窗口变化只重算视口和 HUD 边距。现场已有两种尺寸读数，布局以运行时实值为准。可在本地 `API/Dora.d.ts` 的 `Mouse.position` 示例核对公式。

**W02 的直接操作。** 在检查站柜台前后各画一个固定标记。初始镜头点两点；走到相机开始跟随的位置再点；改变窗口比例再点。每次对照世界碰撞点上画出的十字与屏幕准星中心。这样能把输入坐标问题与角色动作问题分开定位。

### 护送如何判断“该回头了”

`stepEscort` 在 `follow / seekCover / sheltered / frozen / calming` 间切换。跟随时沿地面安全点向周戍身后约一个身位靠拢。街尾给小满单独的低通道锚点，与周戍的翻滚出口在路标重合。每个危险事件先判断距离、遮挡和周戍是否挡在事件与小满之间。有效暴露一次加一格，每个 `dangerId` 只结算一次。未满三格时沿作者连通的安全点选最近掩蔽处，危险消退再出发；三格时停在当前脚下，改为 `frozen`。双人出口检查两人的脚底都在出口区。

| 时点 | 操作前 → 动作 → 操作后 | 输出给画面和声音 |
| --- | --- | --- |
| 第三个有效危险 | 小满恐惧 2、仍在路上 → 读到 `dangerId=7` → 恐惧 3，移动目标清空。该事件再次被读时仍为 3 | 她蹲下捂耳；周戍提前到出口时出现指向她的提示 |
| 靠近 | 周戍距她不超过 64 单位，地面连通 → 点一次 E → 两人进入 60 拍安抚动作 | 提示「E 敲两下」消失，周戍蹲到她的高度 |
| 第 12、36、60 拍 | 第 12 拍敲第一次；第 36 拍敲第二次并将恐惧写为 1；第 60 拍双方恢复移动。安抚动作期间小满保持该姿态 | 第二声她松手，说「我听见了」。此后玩家走向车把，她重新跟上 |

街道的第一次敲柜沿用同一对声音，作为交火解除后的短动作。即使玩家全程把小满护得很好，她也听过这两下。检查站的三格安抚仍由玩家自己走近触发。

## 四、城门的 45 秒和交权的那一步

| 当前状态 | 条件和写入 | 玩家接下来能做什么 |
| --- | --- | --- |
| `gate.ready` | 小满抵达门洞等待点，周戍抵达绞盘，两条件同时满足。先保存这个双人站位，再置 `gateTick=0`，播放「我到了」 | 自由移动、点射、贴掩体、翻滚、发信号 |
| `gate.holding` | 前 900 拍让玩家同时看见鞋尖和门；接着 1200 拍熄灯、开放清晰可见的 Q 标记；最后 600 拍逐步压低门底。敌人从固定配置出场，按阶段进入时触发一次 | 45 秒都给玩家实际操作，接近绞盘有返回门边的短路 |
| `gate.send` | 完成第 2700 拍且周戍存活，撤下预警，冻结敌兵，打开门边交互。到时本身只打开机会 | 走到门边，新点 E 托门。`sentThroughGate=true`，开始数数 |
| `count` | 在城外建立唯一的小满实体。0–6 秒关门；6–17 秒叠化；17–24 秒数到一百，镜头降至她的肩高 | 24 秒前由演出持有控制。期间预先按住的 D、Space 和鼠标都要先松开 |
| `count.walk` | 完成第 1440 拍，出现「D 向前」。新按 D 当步就让现有小满移动并进入城外游玩，余下的环境声继续至 30 秒 | 24 秒就能迈步。若一直等到 30 秒，环境声收尾，角色停在原地，保持「D 向前」直到玩家动身 |
| 已读快速通过 | 同次启动已经读过这段时显示「Enter 跳过」。快进时间线到允许迈步的节点，使用同一个交权函数，并把演出记为已读 | 与正常路径相同，由新按下的 D 迈出第一步；针套在小满手腕上 |

`stepGate` 先结算角色与敌兵再读取计时结果。用越过 `900 / 2100 / 2700` 的那一步更新阶段，剩余秒数显示 `ceil((2700 - gateTick) / 60)`。`stepCount` 在 1440 拍先释放演出所持的角色输入，从下一次新 D 开始走；在同一实体上交权，镜头从数数机位连续跟随。读完的标志在第一次迈步或自然播到 30 秒时写入。

城门第一版配四个出场条目。第 0 秒左窗出现一名敌兵，第 9 秒街尾出现第二名，第 15 秒门灯熄灭并在街尾补一名，第 25 秒左窗再出一名。每个条目有独立的出场 ID 和房间锚点。`gateTick` 跨过该条目的拍数就生成一次。第 35 秒起保留场中敌人，把门下缝隙画得越来越窄。最后十秒玩家逐步走回小满身边，清空敌人也要由玩家按 E 送别。D7 用实玩调出场位置和间隔，45 秒总长固定。

**手推 W07/W08。** 44 秒整时 `gateTick=2640`，暂停五秒再回游戏，仍差 60 个模拟步。最后一步倒地就回绞盘和孩子已就位的检查点；活着才出现「E 送她过去」。若送别时已按住 D，到数数第 24 秒角色仍坐在门边。松开再按，她迈出第一步。这个画面用来验收“换人”是否发生在玩家手上。

## 五、小满线的移动、互动和两道谜题

**移动底座。** 初值设小满宽 28、高 64，蹲高 36。普通走 160 单位/秒，Shift 慢走 80，爬行 80。先做横向扫掠，再做纵向扫掠，以脚底触地更新 `grounded`。跳初速约 320、重力约 1000，顶点约 51 单位。按蹲当步缩短身体；松开时用站姿矩形查询上方，脱离洞顶才站起。攀边在标过的矮台边显示「E 攀上」，18 拍把脚底送到台沿锚，再恢复普通移动。柜内点 E 进入和退出，草丛内低姿和桌下靠实际遮挡隐藏。脚步在落脚时发声，Shift 慢走缩小声圈；蹲姿与慢走同时按时沿用爬行速度。

**E 的含义由站位决定。** `interactionAt` 只取可达、在手边的目标。优先处理已经握住的物件或已进入的柜子，再选当前剧情动作，再选面前最近的场景物件。安抚和塔门只需要一次 `pressed`；车把在 `pressed` 时握住，`held + moveX` 产生位移，`released` 立即停。藏在柜内时 E 始终是「出来」。瓶架、箱把和藏身处的触发矩形在关卡中错开放，玩家按键前就能读到具体动词。

### 谜题 A · 周戍推到哪里，小满就从哪里拉

实体 ID 用 `redCart`。两个房间各有一段短轨，中间共用命名停靠点 `dock`。检查站轨是 `yard → dock`，城外轨是 `dock → pocket`。跨房间只写停靠点 ID，各房间用自己的坐标投影它。外侧拉到一半时，当前车身的实际坐标用于碰撞、图像和握把，同一物件没有第二套开关。

| 地点 | 可直接摆的灰盒坐标，单位为世界单位 | 通过方式 |
| --- | --- | --- |
| 检查站，地面 `y=0` | 周戍 `x=80`、小满 `x=32`；柜台 `[240,340]`，安全锚 `x=264`；危险段 `[380,560]`；车轴从 `x=640` 推至 `768`；双人出口 `[792,928]` | 周戍站在左柄按 E+D；轮到终点落窝。双人到齐且车在 `dock` 才提交 `story.cartDock='dock'`，转去绞盘 |
| 城外，上层装卸台 `y=96` | 小满在 `x=160`；台面从 `x=128` 延至 `512`。外侧手柄在车轴右方 40。车轴从 `x=304` 拉至 `432`，速度 64 单位/秒。上层可沿车的外侧走到手柄 | D 向前，看见红布；从右柄按 E+D 朝空窝拉，松 E 随时停。拉完沿台面回到左端，从 `x<128` 落回下层 |
| 城外，下层 `y=0` | 拱顶从 `x=280` 到 `360`，净高 44。台面临街一侧可行走；车身下缘在下层形成随车移动的阻挡 `[axleX-24, axleX+24]`。出口检查点在 `x=380`，停车窝下方在出口之后 | `dock` 时轮廓 `[280,328]` 正挡住来路。停车后轮廓 `[408,456]` 在出口之外。沿下层向右，按蹲穿过 44 高的拱，到 `380` 提交检查点 |

装卸台剖面要同时看清上层手柄和下层拱口。外侧上层只碰台面，车画在台沿前景。下层使用车身下缘的碰撞框。上层的左侧落差可以跳下，右侧以实墙收住。两个触发点都读下层脚底，局部 `x=380` 保存洞后进度，`x=388` 进入墙根小路，这段走完再进村口。小满身体右沿此时是 `402`，与停车后的车身左沿 `408` 之间仍有 6 单位净空。石阶上的光和回头可见的红布说明返回下层的走法。

```ts
function moveGrippedCart(room, axis, seconds) {
  const cart = room.redCart
  const previous = cart.axleX
  cart.axleX = clamp(previous + axis * cart.speed * seconds, cart.minX, cart.maxX)
  room.actor.x += cart.axleX - previous
  placeCartSkirtAndHandle(cart)
  if (previous !== cart.maxX && cart.axleX === cart.maxX) emit('WheelSeated')
}
```

**手推 W05/W09。** 城外检查点初态车轴 `304`。握住向右拉 1 秒到 `368`，松手，轮廓停在 `[344,392]`，仍挡去出口的路；再握住拉 1 秒到 `432`，同一个落窝声响起。站姿 64 高过不了 44 高的拱，蹲姿 36 可过。钻洞前重试回 `304`；到洞后安全点再重试，车在 `432`，小满在洞后。关卡作者据实际净空允许物理上已能通过的解法。

给装卸台左端摆两级石阶，下层地面 `y=0`、第一级 `y=48`、上层 `y=96`。每级留出至少 40 单位落脚面，低于小满约 51 单位的跳高。先到下层看过洞的人可以原路跳回台面拉车。检查站侧的装卸轨画在通行地面前景，车身承担遮蔽，轮子入窝后，周戍松开握把就能和小满一起沿车后走到双人出口。

### 谜题 B · 声音从瓶子落地的位置发出

村口灰盒全长 720。瓶架 `x=112`，安全观察位 `x=160`，桌下通道 `x=304..416` 且净高 44，第一院通行线 `x=440`。侧窗看得见桌前软土 `x=272` 和桌后砖地 `x=608`。给飞向砖地的瓶子预留高于桌板的抛物线。拾荒者在 `x=464..512` 的路段往返，第一轮从 `464` 起。右侧砖地调查路径连通，门口在他身后。

1. 小满点 E 拿一只瓶，瓶架可重复取，手里最多一只。按住 F 时在射程 480 以内选鼠标指向的可落地表面，画落点与预计声圈。首次切片直接给砖地一个可选落点，D5 加软土和连续瞄点。
2. 松 F 写 `Bottle{from,to,age=0,duration=30}`，手中数量变为 0。每步按进度 `u=age/30` 做水平插值，竖向在两端插值上加 `4*arcHeight*u*(1-u)`；用前后两个位置求和房间物面的首次接触。提前撞到可着落的表面按实际接触位置／材质结算。灰盒窗洞为两个示例落点留出抛物线净空。
3. `stepBottle` 在接触步移走瓶子并发一次 `Sound(position, radius, kind)`。砖地初值 224，软土 80。`stepPatrol` 用敌人脚底到声源的距离判定是否听见。听见后先用 18 拍转头，再以 64 单位/秒前往声源，停 120 拍，随后回到原巡逻段。
4. 观察和调查期间每步查朝向、距离和场景遮挡。看见暴露的小满 24 拍达到发现阈值，图形由疑警变为追逐。追逐优先于新声音。失去视线连续 60 拍后去最后看见的位置查看，再回路线。只有追逐者在同一可达地面段、无隔挡且接触小满才触发 `ChildCaught`。

**手推 W06。** 取瓶后站到 `x=160`，瞄软土 `272`。按拾荒者在落地拍的位置取 `464`，距离 `192>80`，软土发声，拾荒者继续巡逻。回架取瓶，瞄 `608`，松 F 时瓶子离手。落砖拍的距离 `144≤224`，拾荒者转向右侧。从 `464` 去 `608` 需约 2.25 秒，再停 2 秒。小满从 `160` 到 `440`，身体宽 28，脚底中心走到 `290` 时就要蹲，超过 `430` 才能站起。按这段 140 单位爬行、余下 140 单位正常走计算，净移动约 2.63 秒。玩家看见他转过头再出发，抵达门线时还有约 1.62 秒余量。实际判定使用落地拍的敌人位置。

**把同一逻辑铺到后半程。** 村庄第二院把可移动箱放在桌口，玩家先用柜子避开视线，再握箱移开出口；使用板车的位移函数和本院轨道数据。森林沿用巡逻状态，狗先用转耳代替转头，听见脚步的半径取人类配置的 1.5 倍，调查移动取 1.4 倍。第一段把草、落叶、矮台放在一屏里，玩家能看见普通走与慢走对声音的影响。第二段从最后一丛草能看到巡逻折返点，灯下的门廊作为安全区。塔门前留安静的几步给玩家自己走。

### 首通时间怎样调到玩家身上

D4 的第一轮记录九个段落各自的进入和离开时间。D6 请首次玩家走完整局，各段记下实际操作、观察、重试与等待的时间。检查站预算 5 分钟，其中拉车只有约 2 秒，剩余体验来自选安全点、判断小满有没有跟上和把她护送到车边。若这段很快走完，就用现有柜台、敌兵和安全锚再排一处让玩家自己选站位的交火。若玩家停在柜台旁找不到小满，就把柜下的手和周戍回望的方向放进同一镜头。村口若卡在辨认砖地，就先挪窗框和落点，观察下一次试玩。调节以玩家多做了一次有意义的判断为依据，保留随时行动的自由。

制作指导按团队约定使用 DeepSeek 4.1 Flash。D3 给它短片段动作记录和玩家第一次回头的时点，D4 给城门送别到小满迈步的一段录像或带时间戳的文字，D6 给九段实测和玩家原话。每次请它标出一个导致误读的具体镜头、建议改哪处台词或站位、下次试玩应看到什么变化。由程序把改动写进当日调优小时，并在同一个场面复玩。

### Windows 包怎样成为十日成果

D1 指定 Windows x64 构建机，确认 xmake、Visual Studio C++ 工具和可用的引擎源码，预热引擎构建。一小时预算按已有可用环境计。D2 在引擎发行资源副本中设置 `Assets/Script/init.lua` 为独立游戏入口，装入编译后的玩法 Lua、脚本库、字体与场景资源。资源搜索路径依次包含发行副本的 `Script`、`Script/Lib` 和资源根。官方原生打包任务从引擎源码根执行 `xmake app-package --platform=windows --arch=x64 --mode=release --windows-backend=d3d12 --format=zip`。D2 在选定的引擎版本核对该任务，再以实际解压目录双击 EXE、直接看到中文画面、A/D 和鼠标均可操作作为通过证据。把走通的引擎版本、资源布局、构建命令记下来，D8–D10 复用。工具依据为 Dora SSR 官方《How to Package Games as Standalone Applications》第 1–4 节。

D9 记录候选源码提交标识，D10 用 PowerShell `Get-FileHash -Algorithm SHA256 <实际的ZIP路径>` 记录交付文件指纹。交付目录放玩家 ZIP、简短键位与启动说明、版本与对应源码标识；试玩记录留给团队。首通成绩记九段实际耗时和总时长，分别注明是否跳过已读段、重试几次。60 fps、25–30 分钟和 10 秒内恢复均以同一候选包上的实测填写。

### 开工时的第一个可见结果

打开 `init.ts`，把 `Probe.mount(root)` 的挂载点换成 `mount(root)`，先让 `enterRoom('checkpoint')` 画出柜台、两个脚底标记和红布车轮。给 A/D 接固定步移动，给鼠标画一个贴着世界标记的十字。走到镜头开始跟随的位置，再点柜台上的同一个角。**这个角在 Windows 小包里仍能被点准**，才把这条输入链接到周戍点射和小满投瓶。它们后面共用的，就是这条已走通的路径。
