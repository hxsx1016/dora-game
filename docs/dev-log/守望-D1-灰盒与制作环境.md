## 单位与查看方式

全部用**世界单位**，与《守望-逐日开发与代码实现逻辑》第五、六节同一口径，不再另立一套米制。

- 小满高 64、周戍高 88；1 单位 ≈ 1.84 cm（小满 1.18 m、周戍 1.62 m）。
- 走速 160 / 264 单位每秒，慢走与爬行 80；跳初速 320、重力 1000、顶点 51。
- 城门守点 44 秒 = 2640 个模拟步，1 步 = 1/60 秒。

查看：`dora-game` 构建运行后按 `1` 看检查站、`2` 看城外剖面、`Tab` 轮换。地面下方是尺寸注释，右侧竖线是 1 米比例尺（约 54.3 单位）。

灰盒分三个文件：`init.ts` 只建根节点并交给 `Script/watch/app.ts`；`app.ts` 管标签池、窗口变化重排和按键；`graybox.ts` 只画形状与文字锚点。D2 把 `app.ts` 换成正式房间控制器，`graybox.ts` 留作调试视图。

## 共用的一辆车与两个 dock

板车是全篇唯一的跨房间道具，两个房间共用同一组尺寸和一个命名停靠点 `dock`，只写 ID、各自投影坐标。

| 量 | 数值 | 说明 |
| --- | --- | --- |
| 车轴 | 车身中心 | 碰撞、图像、握把都读车轴 |
| 车身宽 | 48（半宽 24） | 停车后左沿 = 车轴 − 24 |
| 手柄 | 车轴 ±40 | 检查站用左柄（−40），城外用右柄（+40） |
| 红布 | 车身左端 | 两个房间都不镜像；城外从门里出来第一眼落在红布上 |
| 车轮半径 | 12 | 落窝即"一响" |
| 停靠点 | 检查站车轴 768 / 城外车轴 432 | 都叫 `dock`，跨房间只交这个 ID |

车辙：检查站 `yard → dock`（车轴 640 → 768，128 单位），城外 `dock → pocket`（车轴 304 → 432，128 单位）。两段一样长，玩家在两个房间推/拉的手感相同。

## 检查站灰盒（军人线，地面 y=0）

从左到右：双人出生点 → 柜台与安全锚 → 城内敌人危险段 → 红布板车从 640 推到 768 → 双人出口。

| 元素 | 坐标（世界单位） | 说明 |
| --- | --- | --- |
| 小满 / 周戍出生 | x = 32 / 80 | 高 64 / 88 |
| 柜台 | [240, 340]，高 60 | 安全锚在 264 |
| 危险段 | [380, 560]，高 120 | 城内敌人触发 |
| 推车 | 车轴 640 → 768 | 周戍站左柄，按住 E + D |
| 停车窝 | 768 | 车能落窝才提交 `story.cartDock='dock'` |
| 双人出口 | [792, 928] | 双人到齐且车在 dock 才开 |
| 城门内侧 | 950 | 墙面收在右端 |

房间总宽 1000、净高 210。推到位的判据是车轴：

    story.cartDock = 'dock'  ⇔  |axleX − 768| ≤ 6 且 两人都在 [792, 928] 前

## 城外剖面灰盒（孩子线，上层 y=96 / 下层 y=0）

这张图是 D1 真正要交的剖面：上层手柄和下层拱口**同时**看见。

| 层 | 元素 | 坐标 | 说明 |
| --- | --- | --- | --- |
| 上层 y=96 | 小满 | x = 160 | 从门里出来就在台面左段 |
| 上层 | 台面 | [128, 512] | 左端 x < 128 可以跳下 |
| 上层 | 拉车 | 车轴 304 → 432，速度 64 单位/秒 | 用右柄（车轴 +40），按住 E + D |
| 上层 | 空窝 | 432 | 拉到位车轮落窝 |
| 下层 y=0 | 拱 | [280, 360]，净高 44 | 只容得下蹲姿（小满蹲高 36） |
| 下层 | 洞后检查点 | 380 | 蹲过拱后提交 |
| 下层 | 出口 | 380 → 388 转入村口 | 读脚底 |
| 左侧 | 石阶 | 0 / 48 / 96 三级 | 每级落脚 ≥ 40，低于跳高 51 |
| 右端 | 实墙 | [512, 600] | 上层到此收住 |

净空是这张图要验证的核心：停车后车身左沿 = 432 − 24 = **408**，小满身体右沿 = **402**，两者之间留 **6 单位**——刚好够她侧身走过、但读起来是"贴着车"。

车在下层形成的阻挡随车轴移动：`[axleX − 24, axleX + 24]`。`dock` 时轮廓 `[280, 328]` 正挡住来路，所以必须先把车拉走，洞口才完整露出来。

## Windows 构建与玩家入口

D2 要在 Windows 冷启动一个小包，所以 D1 必须把路线定死。两条路，按手上有没有 Windows 构建机选：

**A · 官方原生打包（需要 Windows 构建机）**
从引擎源码根执行：

```bash
xmake app-package --platform=windows --arch=x64 --mode=release --windows-backend=d3d12 --format=zip
```

需要 xmake + Visual Studio C++ 工具链，产物在 `build/package/windows/x64/release/d3d12/`，仅支持 x64。这条是官方路线，包最小、启动最干净。

**B · 发行引擎 + 资源目录（当前 macOS 环境可走）**
拿 Windows 版 Dora 发行包，替换 `Assets/` 与入口脚本，只放本游戏用到的 Lua、字体和场景资源，整个目录压成便携 ZIP，双击 exe 即玩。资源搜索路径依次是 `Script`、`Script/Lib`、资源根。

Web IDE 只能导出 HTML、Server 版 HTML、ZIP 工程；`dora cli` 没有 export / publish / windows 子命令。所以"出 Windows 包"这件事本身必须落到 A 或 B，不能靠 IDE。

**玩家入口**：D2 起 `init.ts` 默认进灰盒，D3 走短片段，D4 起"开始游戏"接完整序章；开发期的房间切换键不进发行包。
