# 守望 · 程序实现与验收

函数签名与读写顺序、城门逐拍交权、两道谜题的灰盒坐标与手推样例，以及每日开工顺序，见同目录 [逐日开发与代码实现逻辑](守望-逐日开发与代码实现逻辑.md)。本文保留 W01–W14 作为实际构建的验收编号。

从一个能运行的场景开始。屏幕左边是周戍，后面是小满，前方是一段柜台和一个敌人。玩家朝目标点一次鼠标，小满听见交火后跑向柜台。接上第二个场景，玩家带着同一枚指南针，以小满的身份拉动板车、蹲过低洞。两个场景共用移动、碰撞、输入、镜头和检查点。下文中的数值初值供灰盒调试，原案明确给出的三格恐惧、45 秒守点和 10 秒内恢复单独验收。

## 1. 第一批关卡配置

| 房间 | 从左到右的放置顺序 | 用它验证的行为 |
| --- | --- | --- |
| 检查站灰盒 | 双人出生点 → 柜台及其安全点 → 城内敌人触发区 → 红布板车起点和终点 → 双人出口 | 玩家点中敌人、小满躲避、恐惧满后停步、安抚后继续、两人到齐才通过 |
| 城墙外灰盒 | 小满出生点 → 红布板车末位置 → 车轮后可见的低洞 → 拉车停靠位 → 洞后检查点 | 交接后继承物件和板车位置。拉车前洞口被挡，拉到停靠位后蹲姿可过，站姿会被洞顶挡住 |

区域直接使用 TS 常量配置地面、相机边界、敌人路线、互动件和出口。检查站与城墙外引用同一辆板车，城外加载它在装卸台的停靠位置。画面分远、中、近景三层，移动和交互都在一个侧视平面。

## 2. 程序模块与一帧的执行顺序

路径以游戏仓库为根，按功能首次使用时再建文件。旧原型未提交的入口和游戏文件在正式接入前先记录工作区状态并保存。正式版在独立目录 `Script/watch/` 发展，用约定入口装配。

| 建议位置 | 谁写入、谁调用 | 对外结果 |
| --- | --- | --- |
| `init.ts`、`Script/watch/app.ts` | `AppController` 管理菜单、序章、房间、交接、结局和暂停。入口创建一个根节点和一套输入监听 | `enterRoom` 装载关卡，`finishRoom` 判定下一段，`retry` 恢复检查点，`restart` 清故事进度 |
| `input.ts`、`world.ts` | 输入适配把设备事件收为意图，世界更新持有时钟、位置、速度、碰撞体、区域触发和相机 | 每个固定时间步提交世界快照和本步事件。同一输入可在开发入口重放 |
| `soldier.ts`、`escort.ts` | 士兵处理移动、鼠标指向、射击、掩体、翻滚和信号弹。护送控制器独占小满的跟随目标、恐惧格与安抚进度 | 输出命中、危险、进入安全点、恐惧变化、同行就位等事件 |
| `child.ts`、`perception.ts` | 小满控制器处理地面/空中、站/蹲、慢走、物件交互和声音事件。感知模块读取房间遮挡、巡逻路线与声音落点 | 输出调查、发现、追逐、脱离、抓获。城内敌兵、拾荒者和狗使用各自配置 |
| `rooms.ts`、`checkpoint.ts` | 房间数据定义场景。检查点只在明确触发时复制逻辑字段，恢复由应用控制器一次完成 | `capture` 取得一致快照，`restore` 重建房间并恢复角色、剧情与谜题 |
| `present.ts` | 读取提交后的世界、一次性事件与屏幕布局 | 更新角色和 HUD、播放提示音与字幕。美术替换沿用同一实体 ID 与脚底锚点 |

每帧读取当前角色的输入。A/D、蹲和慢走按住生效，跳、翻滚与敲木在按下时开始。板车用 E 握住和放手。小满按住 F 时用鼠标移动落点圈，松开 F 才生成瓶子。每秒 60 个模拟步更新角色，镜头跟随角色的脚底坐标。Esc 暂停与继续。

按步执行的顺序如下。

1. 将输入映射到当前可控角色，先处理暂停或恢复等应用动作。
2. 更新玩家位移和姿态，做碰撞与脚底判定，产生交互或动作事件。
3. 处理机关、虚拟射击命中、瓶子落地和危险事件，写入本步事件列表。
4. 敌人与护送控制器消费该列表，更新各自状态。敌人的新预警在画面显现，之后的动作按配置延迟触发。
5. 提交本步的角色、物件和房间结果，按动作播放画面与声音。周戍把小满托出门后进入数数段，经过 24 秒将向前走的控制交给小满。

## 3. 士兵与护送

**移动和命中。** A/D 控制士兵横移。鼠标屏幕位置经过视口映射和相机逆变换得到世界准星。左键触发一次游戏内射击意图，检查角色动作许可和游戏冷却，在准星方向选取最先相交的场景阻挡或敌人碰撞区。命中结果同时驱动敌人反馈和画面反馈。首个测试是在镜头平移前后点同一个场景标记，再在两种窗口尺寸下复测。本机 `API/Dora.d.ts` 的 `Mouse.position` 注释提供了 `App.visualSize`、`View.size` 与相机转换示例。

**掩体和翻滚。** 靠近配置的掩体锚点且按住 Shift 后切到掩体姿态，松开退出。Space 开始短位移的翻滚，位移经过同一碰撞处理，结束时回到可移动状态。Q 信号弹的灰盒效果提案为点亮撤离标记并短暂打断一轮敌方预警，让玩家有机会返回小满身边。使用统一动作计时器，暂停时一起冻结。掩体、翻滚和信号弹先各用一处可读的视觉反馈。

**受击与失败。** 灰盒提案给周戍三格体力，每个独立受击事件最多扣一格，清空时广播一次 `SoldierDown`。士兵检查点恢复可行动状态，小满恐惧满时仍能等待安抚。孩子线的抓获则要求追逐者进入接触范围并与小满位于同一可达区域。隔墙相邻、桌面上下或仅出现疑警图标时依旧允许玩家继续躲藏。

**小满跟随。** 在相同地面段保持跟随距离，离开地面段时依次走作者放置的安全点。每个安全点标记所属区域、相邻点及遮挡状态。收到危险事件时先筛可达且有遮挡的点，再按路径长度选最近的一个。找不到候选时退回当前段最后一个已确认的安全点。清除危险后再跟随。双人出口要求两人都在门区，小满尚未赶到时给屏边方向提示。

**恐惧与安抚。** 小满在交火附近暴露，每次有效危险让恐惧增加一格。她躲进掩体后捂住耳朵，周戍挡在前面时给她明确的避险反馈。三格时她停步。周戍走到她身边点按 E，自动完成约一秒的蹲下和两下敲击。第二声响起，小满把手从耳上拿开，恐惧降到一格，说「我听见了」，随后跟上。

**45 秒城门。** 两人进入就位区域后写入守点前检查点，展示任务并开启计时。用一次性时间标记安排压力变化，用当前模拟时间计算剩余秒数。倒计时到零且周戍仍可行动时开放送别交互，只触发一次数数过场。末步同时发生士兵倒地和到零时按前述失败优先处理。死亡恢复为守点前状态，上一轮实体、预警、提示和时间标记一起释放。测试在 44 秒暂停五秒，恢复后仍需完成余下的一秒。

## 4. 小满、环境交互与潜行

**接手时。** 应用控制器恢复指南针和纸条，读取军人线留下的场景标记，创建小满的可控角色。等待一次新的物理按键后才接受动作。Shift 改为慢走，Space 改为跳跃，S/Ctrl 蹲伏，E 上下文交互，F 投瓶。首次遇到不同操作时各显示一次简短提示。切线瞬间保留仍在按住的键，直到松手，避免承接军人最后一次操作。

**移动与交互。** 小满按 Space 跳起，按住 S/Ctrl 低身穿过桌底，走出洞口后松手站起。每处交互把动作直接写在物件旁。点 E 拿瓶、攀边、进出柜子或敲塔门。按住 E 再按 A/D 推拉车或箱，松 E 即放手。灰盒把瓶架、箱把和藏身处摆在可区分的站位。

**声音与观察。** 按住 F 时出现落点圈，鼠标在砖地与软土间移动能看出预计声圈大小。松手后瓶子从小满手中飞向落点，碰地时才出现实际声圈。听见声响的巡逻者先转头，再走到落点，停留片刻后回原路。玩家在他转身时看见走到桌下的机会。视线接触让警觉上升，发现后追逐，进到遮挡后脱离。狗共用这套行为，听觉范围和走到声源的速度由森林区域配置。小满被抓回到本段检查点。

**谜题进度。** 板车有稳定 ID、两个停靠位置和局部移动进度。军人线出口把终点写为跨线故事标记，孩子线进入时从标记建立车和低洞的初态。洞的阻挡取决于车的实际位置，恢复检查点时一次重建二者。村庄配置可回到的取瓶点，瓶子落空、投错或玩家被抓后都有可执行解。关卡验收先用错误落点，再回头取瓶走出桌下出口。

## 5. 存储、恢复与开发调试

| 数据寿命 | 字段 | 读写时机 |
| --- | --- | --- |
| 本局故事 | 当前区域、可控角色、指南针与纸条归属、城门交接标记、板车跨区标记 | 序章交物、军人线离场、孩子线进入、尾声完成时事务式写入 |
| 当前检查点 | 房间 ID、角色出生锚点、已生效的故事标记、稳定物件位置、可用瓶子和本段初始敌人配置 | 在可站立的安全区域提交。恢复时先装载配置，再恢复持久字段，最后开放输入 |
| 当前房间瞬态 | 速度、动作计时、恐惧/追逐状态、临时声音、粒子、按键边沿、守点倒计时 | 按房间或检查点约定初始化。守点中途失败以守点前快照重新进入 |

检查点保存本次游玩的进度。退出重开从序章开始。开发入口可直达某个区域，正式入口从废墟开始。布局使用当前窗口尺寸计算，角色格局、门、车轮和计时读取房间状态。
