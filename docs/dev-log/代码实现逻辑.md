# 《借我六步》代码实现逻辑

> 历史原型实现说明，适用于已做出的脚印回放解谜。正式项目「守望」的开发方向见同目录 `PROJECT_OVERVIEW.md` 页首。

你可以从 `advance(level, before, command)` 开始写。它每次接收一个命令，返回新局面与结果。键盘、动画和 Dora 的帧更新都在它外层。第一项交付是跑通 T12 和 T15，同一张地图上，一条录制会被门挡住，另一条能通关。这两种结果出来以后再画门。

## 1. 规则层的参考实现

这一段 TypeScript 可独立执行。实现时，关卡解析与查询放进 `Script/game/levels.ts`，初态、回声和 `advance` 放进 `Script/game/turn.ts`。坐标表示为整数格，棋盘边界在转换位置时统一检查。局面和路径只读，录制时每次追加最多复制六个元素。合作时所有操作共享已确认的路径。

```ts
export type Position = Readonly<{ x: number; y: number }>;
export type Phase = "REC" | "PLAY" | "WON";
export type Direction = "L" | "R" | "U" | "D" | "W";
export type Command = Direction | "Confirm" | "Retry" | "Rerecord";
export type Outcome = "ok" | "empty" | "outside" | "wall" | "closed_A" | "closed_B"
  | "confirmed" | "auto_confirmed" | "retried" | "rerecorded" | "won" | "inactive";
export type Level = Readonly<{ rows: readonly string[]; width: number; spawn: Position }>;
export type State = Readonly<{
  phase: Phase; body: Position; path: readonly Position[]; ticks: number;
}>;
export type Result = Readonly<{ state: State; outcome: Outcome }>;

export function parseLevel(id: string, input: readonly string[]): Level {
  const width = input.length > 0 ? input[0].length : 0;
  if (width === 0) throw new Error(id + " 地图为空");
  let spawn: Position | undefined;
  let exits = 0;
  const counts: Record<string, number> = { a: 0, b: 0, A: 0, B: 0 };
  for (let row = 0; row < input.length; row++) {
    if (input[row].length !== width) throw new Error(id + " 行宽错误 y=" + row);
    for (let col = 0; col < width; col++) {
      const tile = input[row].slice(col, col + 1);
      const where = id + " (" + col + "," + row + ")";
      if ("#.SEabAB".indexOf(tile) < 0) throw new Error(where + " 未知地形 " + tile);
      if (tile === "S") {
        if (spawn !== undefined) throw new Error(where + " 重复起点");
        spawn = { x: col, y: row };
      }
      if (tile === "E" && ++exits > 1) throw new Error(where + " 重复出口");
      if (tile === "a" || tile === "b" || tile === "A" || tile === "B") {
        counts[tile]++;
        if ((tile === "a" || tile === "b") && counts[tile] > 1) {
          throw new Error(where + " 重复踏板 " + tile);
        }
      }
    }
  }
  if (spawn === undefined || exits !== 1) throw new Error(id + " 缺起点或出口");
  for (const group of ["A", "B"]) {
    if ((counts[group.toLowerCase()] === 1) !== (counts[group] > 0)) {
      throw new Error(id + " 门和踏板未配对 " + group);
    }
  }
  return { rows: input.slice(), width, spawn };
}

function tileAt(level: Level, pos: Position): string {
  if (pos.x < 0 || pos.x >= level.width || pos.y < 0 || pos.y >= level.rows.length) return "outside";
  return level.rows[pos.y].slice(pos.x, pos.x + 1);
}

const offsets: Record<Direction, Position> = {
  L: { x: -1, y: 0 }, R: { x: 1, y: 0 }, U: { x: 0, y: -1 },
  D: { x: 0, y: 1 }, W: { x: 0, y: 0 }
};

export function start(level: Level): State {
  return { phase: "REC", body: level.spawn, path: [], ticks: 0 };
}

function playback(level: Level, path: readonly Position[]): State {
  return { phase: "PLAY", body: level.spawn, path, ticks: 0 };
}

export function echoAt(level: Level, state: State, ticks: number): Position | undefined {
  if (state.phase === "REC") return undefined;
  if (ticks === 0) return level.spawn;
  return state.path[Math.min(ticks, state.path.length) - 1];
}

function pressed(level: Level, group: string, body: Position, echo: Position | undefined): boolean {
  const plate = group.toLowerCase();
  return tileAt(level, body) === plate || (echo !== undefined && tileAt(level, echo) === plate);
}

export function shownGroups(level: Level, state: State): string {
  if (state.phase === "REC") return "";
  const echo = echoAt(level, state, state.ticks);
  return (pressed(level, "A", state.body, echo) ? "A" : "")
    + (pressed(level, "B", state.body, echo) ? "B" : "");
}

export function advance(level: Level, before: State, command: Command): Result {
  if (before.phase === "WON") return { state: before, outcome: "inactive" };
  if (command === "Rerecord") return { state: start(level), outcome: "rerecorded" };
  if (command === "Retry") {
    if (before.phase !== "PLAY") return { state: before, outcome: "inactive" };
    return { state: playback(level, before.path), outcome: "retried" };
  }
  if (command === "Confirm") {
    if (before.phase !== "REC") return { state: before, outcome: "inactive" };
    if (before.path.length === 0) return { state: before, outcome: "empty" };
    return { state: playback(level, before.path), outcome: "confirmed" };
  }

  const offset = offsets[command];
  const nextBody = { x: before.body.x + offset.x, y: before.body.y + offset.y };
  const tile = tileAt(level, nextBody);
  if (tile === "outside" || tile === "#") {
    return { state: before, outcome: tile === "#" ? "wall" : "outside" };
  }
  const nextTicks = before.ticks + 1;
  const nextEcho = echoAt(level, before, nextTicks);
  if (command !== "W" && (tile === "A" || tile === "B")) {
    if (before.phase === "REC" || !pressed(level, tile, before.body, nextEcho)) {
      return { state: before, outcome: tile === "A" ? "closed_A" : "closed_B" };
    }
  }

  if (before.phase === "REC") {
    const path = before.path.concat([nextBody]);
    if (path.length === 6) return { state: playback(level, path), outcome: "auto_confirmed" };
    return { state: { phase: "REC", body: nextBody, path, ticks: 0 }, outcome: "ok" };
  }
  const reachedExit = tile === "E";
  const state: State = { phase: reachedExit ? "WON" : "PLAY", body: nextBody, path: before.path, ticks: nextTicks };
  return { state, outcome: reachedExit ? "won" : "ok" };
}
```

`nextEcho` 只参与本次通行试算。画面在成功提交后用 `shownGroups(level, result.state)` 更新门，拒绝时只更新提示。如果以后改成“开门后永久开启”，需要改的是状态和 `pressed` 的契约，现有的逐拍验收数据也要随之调整。

## 2. 将一条输入接到整款游戏

`init.ts` 建立一个应用根节点、一个棋盘层和一个 HUD，读取启用的关卡列表。`Session` 持有 `roomIndex`、当前局面、页面类型、焦点状态、已按住的键、会话序号和当前动画序号。控制器分清物理键和规则命令。方向键右送 `R`，字母 R 键送 `Retry`。进入 `WON` 后回车送 `Continue`，只有控制器处理 `Continue`。最后一关先到结束页，结束页回车才重开第一关。

```text
收到 keyDown(physicalKey)
  窗口有焦点且该键首次按下时，把键记入 held，按当前页面解析动作
  若动作是 Continue 或 PlayAgain，由房间列表选择下一页面，并结束本次分发
  动画期间允许 Retry 和 Rerecord 插队，其余游戏动作即时丢弃
  保存 before，执行 result = advance(level, before, command)
  result.state 与 before 是同一对象时，只记录拒绝原因并按需提示，然后返回
  将 result.state 赋给 session.state，然后处理这一次结果
  若结果为重录或重走，先使旧动画序号失效，再清理动画，直接绘制新局面
  若结果为手动或自动确认，用结果中的路径刷新六个槽位，人物复位到起点
  若结果为 won，显示通关与继续操作，消费本次唯一通关反馈
  其他接受动作按 before 和新状态更新棋盘；开启插值时捕获会话序号与动画序号

收到 keyUp(physicalKey) 时，无条件移除 held 中的该键
```

记录按键放在动画过滤之前。这样玩家在动画中按住一个键，结束时也要经过抬起和再次按下才能触发下一步。换关与重置保留 `held`，避免长按回车直接跳过两层页面。失焦清空 `held`，取消插值，把角色放回已提交格。聚焦恢复时以新的物理按下边沿继续，在目标浏览器实测“切走期间一直按住”和“切走期间松开”两条路径；如果收到系统重发，恢复时以一次点击棋盘重新启用键盘，HUD 给出“点一下继续”。

**旧回调的处理。** 每次取消插值、切房或失焦，先递增动画序号，再撤销表现。完成回调只有在捕获的会话序号、动画序号都与当前值相等时才可清输入锁。一次重录后马上开始的新动画也有自己的序号。这样旧回调不会解开新动画的锁。首版用瞬移，棋盘与 HUD 共用同一快照即可。

## 3. 棋盘、预览与反馈

`Board.mount(level)` 按格建立背景、地形、关门条与板符号。将 A 和 B 的所有门格按组登记，第三关同组的两格 A 一起刷新。`Board.draw(state)` 按已提交快照更新本体、回声与门。`Hud.draw` 接收阶段、路径、有效拍数和结果码。每次换房替换房间节点，应用输入节点贯穿整局。

网格用左上原点存储。设 `left`、`top` 是棋盘左上角在 Dora 父节点局部坐标中的位置，格宽为 `size`，则格中心为 `left + (col + 0.5) × size`、`top − (row + 0.5) × size`。布局先扣除 HUD 和边距，以剩余宽度除列数、剩余高度除行数，较小值作为格宽上限。窗口变化后静态地形、脚印、两角色一起按同一转换重排。

六个脚印槽直接读取 `path`，第一个箭头比较起点与 `path[0]`，以后逐项比较前一个落点。相邻坐标相同的项显示等待符号。合作时若 `ticks < path.length`，下一落点是 `path[ticks]`；否则显示“回声停在这里”。本体和回声重叠时保留外环。首帧显示游戏名、当前任务和可按的键，第一次错解也能找到重录入口。

| 规则返回 | 棋盘 | 玩家得到的反馈 |
| --- | --- | --- |
| `closed_A` 或 `closed_B` | 维持提交过的局面，可短闪受阻的门 | 若当前门开、候选回声会离板，提示“下一拍回声会离开 A”。其他情况提示需要踩哪组板 |
| `empty` | 零步录制画面 | 提示先走一步，或按空格留下等待 |
| `auto_confirmed` | 双方回 S，六槽完整 | “已录满六步。现在轮到你与回声合作。”第六次按键的落点取路径末项 |
| `retried` / `rerecorded` | 分别保留或清空整条脚印 | 显示“按原脚印重走”或“开始录新脚印” |
| `won` | 固定出口上的角色，显示本关完成 | 中间关给出进入下一关的按键，末关给出查看结局的按键 |

## 4. 用第二关定位实现错误

第二关的 `baS.ABE` 从左至右编号 0 到 6。两条输入只有录制阶段是否等待这一处差异。

| 输入 | 上一步的局面 | 当前试算 | 函数应返回 |
| --- | --- | --- | --- |
| `LL / RR` 的最后一个右移（T12） | 本体 3，回声 1，A 当前开启，有效拍 1 | 回声候选去 0 踩 b，本体想从 3 进 A | `closed_A`，仍是原局面对象。显示的 A 仍开启 |
| `WLL / RR` 的最后一个右移（T13） | 本体 3，回声 2，门全闭，有效拍 1 | 回声候选去 1 踩 a，本体想从 3 进 A | `ok`，本体 4、回声 1、有效拍 2，显示 A 开 |
| 接上一步再右移（T14） | 本体站 A 门，回声踩 a | 回声去 0 踩 b，本体从 A 进 B | `ok`，本体 5，当前只有 B 开 |
| 再右移（T15） | 回声已走完，本体站 B 门 | 回声留在 0，本体进入 6 | `won`，有效拍 4，结算一次 |

`advance` 对 T12 错了就查 `pressed` 的两个位置参数。T12 对了而屏上的门提前关闭，就查视图是否读取了 `nextEcho`。若两个都对、玩家长按却连续走两步，就对照输入层每次 `keyDown` 生成的命令序列。三个检查分别排除一整层问题。

## 5. 把开发检查接到交付件

开发回归入口逐行读取验收向量，从 `start` 开始投递命令，末态依次序列化阶段、本体格、录制落点、有效拍数、回声格、当前门组和最后结果码。测试读取 CSV 的职责在开发端。正式游戏只需关卡数组和同一份规则。

本次直接提取第一节代码，在 Node 24 下执行 34 组向量的 195 次命令，七个末态字段全部匹配。每一步均核对输入局面未被改写，拒绝分支返回原对象。另用 11 张无效地图检查读入失败路径。Dora 编译后的 Lua 行为和导出包内的键盘输入分别由 D2 回归与浏览器实测覆盖。

D1 导出带项目标记、中文文字和可移动方块的桌面浏览器包。D3、D5、D8 将同一个导出入口分别用于单关、全流程和发行候选。每次导出都在新目录解压完整 ZIP，在目标浏览器打开 `index.html`，点到棋盘，验证方向键、空格和回车。检查页面滚动、菜单焦点、失焦恢复、中文缺字和漏打包资源。D10 对最终交付的 ZIP 记录 SHA-256，将该文件分发给一台无开发环境的目标设备，离线打开并走完整局。若修复后重新导出，重新计算该份归档的指纹，完整重跑交付检查。
