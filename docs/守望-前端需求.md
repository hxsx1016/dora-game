# 《向西守望》前端需求与联调验收

新版分线、数到二十时的背景渐变、协作换弹和双通关彩蛋以[双线前端交付单](向西守望-双线前端交付单.md)为准。下文供现有接口对照。

交付目标为 2026 年 12 月 1 日的 Windows x64 键鼠离线版。这里的前端指 Dora SSR 客户端的画面、界面与声音表现。需求基于 `b467d02`，适用于周戍护送小满、城门交权、小满独自抵达北塔的八个房间。

**时代与风格以[明朝全局美术设定](守望-明朝全局美术设定.md)为准。** 包括标题、HUD、封面和特效，不只换背景。D1/D2 截图只对照尺寸与位置。下文保留原联调基线；事件的实际字段和状态以[玩法交付记录](守望-玩法交付-2026-11-23.md)为准，美术换装不提出新接口。

## 一、交付范围与代码入口

| 负责方 | 交付内容 |
| --- | --- |
| 前端同事 | 像素角色与场景接图、动作播放、镜头与准星对齐、HUD、叙事字幕、音效触发、正式包使用的本地资源清单。提交 TypeScript 后按仓库流程同步生成 Lua。 |
| 玩法开发 | 角色位置与姿态、输入采样、战斗及听觉结算、护送状态、剧情计时、重试与切房。提供表现所需的只读数据和一次性事件。 |
| 双方联调 | 用同一构建比对模拟拍、画面和声音。前端交付同段录屏或关键帧，玩法侧交付对应的逐拍读数。 |

现有画面从 `tickPlay()` 进入，每个渲染帧完成模拟步后调用 `Play.draw()` 和 `playHud()`。角色、场景、界面三处可分别接入。坐标和原始截图可直接从仓库取得。[入口与 HUD](../Script/watch/app.ts) · [场景绘制与坐标换算](../Script/watch/play.ts) · [像素画布基准](守望-D2-输入与试玩层.md) · [检查站基准图](d2-像素画布-检查站.png)

## 二、画布、镜头与界面

- **画布。** 使用现有 320×180 逻辑画布，每个美术像素对应 2 世界单位，一屏覆盖 640×360。720p、1080p、1440p 分别按 4×、6×、8×绘制。其他宽高比保持整数倍率，余量居中留边。贴图使用最近邻采样，世界位置保留小数，最终绘制才取整。
- **镜头和准星。** 人物、场景与落点预览共用 `worldToScreen()` 和同一帧相机。窗口指针沿现有输入换算进入世界坐标。检查站使用已处理 `originX` 的世界坐标。换人时镜头转向小满，军人准星随控制权交接撤下；小满瞄瓶时才显示投掷预览。
- **HUD 与字幕。** 城门显示体力格和守点剩余时间，护送段呈现小满的恐惧状态，暂停、倒地等待确认、片尾分别可辨。中文沿用包内字体。正式界面仅保留状态、叙事字幕和当前可用动作的短标签。坐标、批次日志、快跳键表归开发视图。字幕避开柜边的手、板车手柄和塔门敲击位置。
- **静音可读。** 预警用抬肩与收紧的断线，挡下用柜沿碎屑，受击用角色缩肩与空心血格。红布使用布条轮廓，恐惧变化同时改变小满姿势。静音或灰度画面仍能区分这几种结果。

## 三、角色与八房间的画面交付

周戍按明朝守卒画素盔、束带和短袄，敌方火器手用窄身直衣摆区分，小满用双髻、布鞋和护住针套的手识别。[Warped City 动作样片](https://opengameart.org/content/warped-city)只可参考步相和姿态，不直接用现代角色定稿；其 71×67 帧与 `(35,67)` 脚底锚点只描述原素材。成品沿用游戏现有世界锚点，小满站立高 32 美术像素、蹲姿高 18 像素。首批覆盖待机、移动、贴靠、受击与下列房间动作，服装和火器外形不改变结算。

| 房间 | 必交画面与动作 | 对齐玩法的关键点 |
| --- | --- | --- |
| `prologue` 序章 | 柜后、蹲着的小满、周戍递针套、纸条收入针套 | 递物第 12 拍两手相接，36 拍纸条收好，60 拍小满起身跟随。 |
| `street` 街道 | 跑动点射保留腿部步相，翻柜时手压柜沿，小满露出扶柜的手 | 冲击落在柜沿与角色受击使用不同反馈。柜边回应接玩法侧确认的街道阶段。 |
| `checkpoint` 检查站 | 周戍贴靠、小满捂耳／抬眼、左柄推车、红布与车轮落窝 | 安抚第 12、36 拍两次手板接触，第 60 拍恢复跟随。握柄时脚步随车轴位移，停轴即停步。 |
| `gate` 城门 | 敌人等待／举枪／结算，周戍托门，门底冷光收窄，换人后小满护住针套 | 预警窗 36 拍。守点达 2700 拍且进入 `gate-send` 才收准线。数数期间画静止姿势，玩法进入 `gate-walk` 才迈步。 |
| `outside` 城外 | 同一辆红布车改由小满抓右柄，露出低拱和墙根石阶 | 红布固定在车身左端。车轴从 304 到 432，蹲姿与 44 世界单位高的拱洞匹配。重试首帧按恢复后的车位和人位绘制。 |
| `village` 村口 | 拾瓶、抬手、出手、飞行、触地声圈，拾荒者依次停脚、转头、走向落点 | 预览圈使用玩法给定的缓存端点。只有落地事件启动声圈与音效；圈大小取玩法提供的材质结果与半径。 |
| `forest` 森林 | 狗转耳、起跑、低头嗅闻、返回，小满在草后仍可见剪影 | `ear` 阶段保持转耳姿势，进入 `chase` 才跑。草丛前景给耳尖和小满轮廓留出空间。 |
| `tower` 北塔 | 小满主动敲门，提灯、递针套、登记簿空行、片尾 | 两声在进入敲门的当拍及第 12 拍，第 36 拍进递物段。递物段独立计时，60 拍递物、120 拍空行、180 拍片尾。 |

## 四、玩法与前端的数据约定

**当前可读。** `Play` 已有 `player`、`partner`、`childMode`、`phase`、`phaseTick`、`gateTick`、`hp/maxHp`、`coverNear/coverHug`、`escort.state`、`cartAxle/cartDocked`、`bottleFly`、`scavState`、`dogState`。前端每帧读最后一个模拟步的状态用于站位、姿态和 HUD。持续处于 `coverHug` 只驱动贴靠姿势。正式联调从运行中的 `Play` 取数。

**待玩法侧提供。** 下表为建议事件契约，字段名供双方在首轮联调时定稿。所有坐标均为世界单位，时间均为 60 Hz 模拟拍。

| 事件 | 最小数据 | 前端消费结果 |
| --- | --- | --- |
| `shotResolved` | 发起者 ID、起点、实际终点、结果、命中对象 ID（如有） | 当拍点射动作，终点显示墙屑或命中反馈。 |
| `coverBlocked` / `actorHit` | 角色 ID、接触点、掩体 ID 或剩余体力 | 柜沿扬灰或人物缩肩。血格读取同拍结算后的体力。 |
| `knock` | 发起角色、场景用途、敲击序号、接触点 | 手势与木声共用同一事件；塔门和安抚分别取本段节拍。 |
| `cartDocked` | 房间、车轴落窝位置 | 车轮轻沉一像素，播放一次木轮声。重试恢复的已落窝状态直接画静帧。 |
| `bottleLanded` | 实际落点、地表材质、声圈半径 | 在该点播放一次落地声并展开声圈，持续绘制飞行轨迹时只读瓶的位置。 |

事件由玩法侧附上本局标识、模拟拍和递增序号。每个渲染帧按序消费其间**所有**模拟步的事件，再绘制最终姿势。0 步帧可重画当前状态，同一敲击只播一次。暂停冻结动作与计时；换房、R 重试、片尾再玩均切换到新实例，随之移除旧房准线、声圈和未播事件。缺少事件时前端可用带固定拍号的样例做表现联调，实际触发时机由玩法侧验收。

## 五、交付顺序与验收

| 日期 | 前端交付 | 复核方式 |
| --- | --- | --- |
| 11/23–24 | 检查站首段样片、首批图集、角色锚点、状态与事件字段确认 | 同框看清柜边小满的手。静音区分举枪、挡下、受击。镜头移动前后，柜角准星与世界标记偏差均不超过 1 美术像素。 |
| 11/25–26 | 接齐八房间动作、HUD、叙事字幕与音效；正式素材随便携包复制 | 录下检查站安抚与塔门两敲，对照各自的拍号。村口取松手、触地前、触地三帧，声圈只在触地帧出现。打包参考[现有组包脚本](../tools/make-windows-pack.sh)。 |
| 11/27–28 | Windows 真机检查 720p、1080p、1440p 及一次非 16∶9 窗口 | 用解压后的默认入口确认资源离线可读、中文完整、细线清晰、窗口缩放后准星对齐。城门第 44 秒暂停并恢复，确认动画停在同拍；重试、换人、再玩各查一次旧画面残留。 |
| 11/29–12/01 | 11/29 候选构建，11/30 冻结，12/01 交付 | 随包提交资源目录、授权、Git 提交号、ZIP 校验值及上述录屏或截图。记录实际系统、分辨率和结果；仅跑过模拟回放的项目保留“Windows 待测”。 |

基线联调有三处已知依赖。街垒旁 `x=490/505` 的姿态与挡下结果需要玩法侧统一；城门致命同拍的 E 可能被重开流程消费；村口竖直投瓶可能在松手首拍过早落地。前端按实际事件显示并记录拍号，玩法侧负责修正结算后共同复测。现有脚本供逐拍对照。[结算断言](../tools/verify-d6.lua) · [城门回放](../tools/replay-gate.lua) · [八房间回放](../tools/replay-d5.lua)
